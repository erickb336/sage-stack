4How it works

A task passes four guards in its normal flow. Only the merge check can refuse.

Before the build
Brief

The brief lists recent fixes of the same files, and the chief adds a find-the-cause step when they share a symptom.

In the review
Patch signal

When new code gets more complex in lines that a recent fix changed, the reviewer decides if it is one more special case.

On each new commit
Decay check

Sage compares the changed files before and after for size, complexity and copied code; worse needs a one-line reason.

Before the merge
Merge check

The merge check reads the recorded result and refuses only worse code with no reason.

On the side, when you ask
Scan

Sage ranks the files that decay most and drafts up to 5 cause tasks for you to pick.

The scan finds old decay. The four guards stop new decay.

Follows: SonarQube's "clean as you code" (judge new code only), Google's Tricorder (a person judges a noisy signal), CodeScene's hotspots (the scan). Unlike Betterer, it adds no file to your project.

6What the agents do

Chief

Lists recent fixes in each brief, and adds a cause step when they share a symptom.

Implementer

Names the shared cause first, or writes one reason line for worse code.

Lead

Runs the decay check on each new commit, and records the reason.

Code reviewer

Judges each patch signal and reason; one more special case gets a band-aid finding.

Merge check

Reads the recorded result. It runs no tool.

Scan

The chief runs it when you ask and offers it at each release.

7Rules

Never blocks

A tool failure never blocks. The board shows "not measured" in grey.

Shadow first

For 14 days nothing refuses. Refusals start only after your yes.

One refusal

The merge check refuses only worse code with no reason.

Better passes

A change that is better overall needs no reason, so a cause fix never waits.

Worse means

Complexity over 15, a file over 1,000 lines that grows by more than 50, or 50 tokens of copied code.

New code only

Only changed lines count. Old decay never stops a new pull request.

Narrow signal

The patch signal reads the changed lines plus 3 lines around them, not whole functions.

No new cycle

A reason changes no code, so it starts no new review cycle.

Isolated

The tools only read the project: no project code runs, and no network.

Noise limit

A measure that asks on over 10% of pull requests for 30 days turns off, and you hear why.

Skipped

Design, docs-only and investigation tasks get no check.

Any project

Same in Claude and Codex, for any language; size and copies still count where complexity cannot.
