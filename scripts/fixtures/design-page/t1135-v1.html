4How it works

States

A project is in one of five states. Time and work move it by itself between the first four lists. Only you archive and restore.

Active

Work in the last 14 days: a run, a task added, a question answered or a merge.

Quiet

No work for 14 days. It stays in the picker, lower down, with "3 weeks ago" beside it.

Older

No work for 30 days. It folds into the Older list by itself and comes back when work starts.

Archived

You put it away. The chief starts nothing in it. The logbook stays whole.

Restored

You brought it back. The board shows "Welcome back" until you open it or work starts.

Nothing in any state deletes a logbook.

Prior art. The picker follows the recent-projects list of code editors (VS Code, JetBrains): most recent first, old ones out of the way. Archive follows Slack channels and GitHub repositories: an archived one stays whole, shows a banner and comes back with one action. Linear differs: it archives by itself after a set time. Sage only folds by itself, because archive also stops new work, and that stays your choice.

7Rules and edge cases

Open

The board opens on the project of the chat that sent the link. With no project in the link, it opens on the last project you looked at.

One project

Overview, Tasks, Agents and Pull requests show one project only. No page lists another project's tasks. There is no "All projects" view.

Agent count

The top bar counts agents in all projects, against the shared limit of 20, and says "all projects".

Signal

"N other projects need you" counts shown projects with an open question. Older and archived projects do not count.

Fold

After 30 days with no work, a project folds into Older, open tasks or not. Any new work brings it back. My recommendation; see choice 1.

Keep

Archive changes one setting. It keeps every task, state, finding, review, answer and page. Nothing deletes a logbook.

Running agents

Archive lets running agents finish their run. Then the chief starts nothing new. My recommendation; see choice 2.

Pull requests

Open pull requests stay open on GitHub. Nothing merges in an archived project, also with autopilot on.

Claude and Codex

The archive setting lives in the logbook. Both apps read it, so a project archived in one is archived in the other.

Two clones

Two clones of one repository are one project in the picker. Archive and Restore write to every logbook of that repository.

Your chat's project

If the chat's project is archived, the board still opens on it, with the banner and Restore.

Last project

You can archive the last project. The board then shows the "all archived" picker.

Writes

Archive and Restore need a paired browser, like the board's other writes. Without one, the confirm offers pairing or the chat.

Stats

Stats counts all projects, archived ones too, and marks them. It never shows a number that the logbooks do not hold.

10Under the hood

For engineers. Much of the data is there already. The board model sorts projects into the lists needs, active (14 days), idle and archived, and the state tool's project setting archived folds a project. The model counts a project as archived only when every logbook of its repository says so. This design adds an Older list (30 days), puts the project key in the board link and the address, filters each page by that key, and adds one paired write that sets archived on every logbook of the repository. The chief's run start and merge check read the setting. Stats reads runs (start, end, tokens), tasks (state, rounds), merges and open questions; money and human time are not in the logbooks. The real numbers on this page come from the logbook folders on this Mac on 16 Nov 2026: the last file change of each folder (an upper bound for the day of the last work) and the open tasks in each task list. No engineering check ran on this design yet.
